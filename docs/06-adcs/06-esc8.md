# ESC8: NTLM Relay to AD CS Web Enrollment

## Objective

This test assessed whether NTLM authentication could be coerced from a domain system and relayed to the AD CS Web Enrollment endpoint to obtain a certificate for the victim computer account.

## Security condition

The assessment confirmed that:

- Web Enrollment was enabled on `BRAVOOS`
- The endpoint accepted Windows authentication
- NTLM was available in the lab
- A domain computer could be coerced to authenticate to the assessment system

An HTTP `401 Unauthorized` response from the enrolment endpoint did not mean the service was absent. It confirmed that the endpoint was reachable and required authentication, which made it relevant as a relay target.

## Relay setup

Impacket's `ntlmrelayx.py` was configured to relay authentication to the Web Enrollment endpoint and request a suitable machine sertificate:

```bash
ntlmrelayx.py -t http://10.4.10.23/certsrv/certfnsh.asp -smb2support --adcs --template DomainController
```

## Certificate authentication

The machine certificate was used to obtain a Kerberos TGT with PKINIT. The resulting ticket then allowed credential extraction from the domain controller.

```bash
python3 gettgtpkinit.py -cert-pfx MEEREEN\$.pfx 'essos.local'/'meereen$' 'meereen.ccache'

export KRB5CCNAME=/home/kali/Documents/ADCS/meereen.ccache
```

## Result

A network authentication from a domain controller was converter into a certificate for its computer account. The certificate enabled authentication as the domain controller and exposed domain credential material.

## Security impact

ESC8 can turn one coerced NTLM authentication into domain compromise. The certificate may remain esable beyond the original NTLM session and is not invalidated by changing the computer account's interactive password in the same way as a normal user credential.

## Detection opportunities

- NTLM authentication from domain controllers to unusual hosts
- Web Enrollment requess for machine or domain-controller templates from unexepcted sources
- Certificate issuance immediately following RPC coercion activity
- PKINIT authentication for a computer account from a nonstandard system
- Relay-tool network pattern and unusual access to `/certsrv/`

## Mitigation

- Disable AD CS Web Enrollment if it is not required
- Require Extended Protection for Authentication and secure channel binding where supported
- Reduce or disable NTLM
- Require SMB signing and LDAP signing/channel binding as appropriate
- Restrict certificate template enrolment permissions
- Harden systems against authentication coercion and limit exposed RPC services
- Monitor certificate issuance for computer and domain-contoller identities

## Key takeaway

ESC8 demonstrated how trust can cross protocols: coerced RPC authentication was relayed over HTTP to obtain a certificate, and that certificate was then used for Kerberos authentication. Defending only one protocol would not have broken the entire chain.
