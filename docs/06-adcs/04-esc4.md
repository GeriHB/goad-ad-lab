# ESC4: Dangerous Certificate Template Permissions

## Objective

This test assessed whether the low-privileged `khal.drogo` account could modify a certificate template and convert it into an authentication escalation path.

## Security condition

Certipy identified dangroues control permissions over the `ESC4` template, including rights equivalnet to full control, ownership modification, DACL modification, and property writes.

## Result

A standarad user with excessive object-control permissions converted an non-exploitable template into one that issued a privileged authentication certificate.

## Security impact

Template ACLs are as important as the visible enrolment settings. A user who can change the template can alter subject handlling, EKUs, approval requirements, or enrolmlent permissions and create a new escalation path without controlling the CA itself.

## Detection opportunities

- Changes to certificate-template attributes
- Ownership or DACL modifications on template objects
- Template changes immediately followed by certificate issuance
- Low-privileged accounts writing to Public Key Services objects
- Restoration or repeated toggling of sensitive template settings

## Mitigation 

- Restrict template ownership and modification to a small PKI administration group
- Remove inherited or unnecessary `WriteDACL`, `WriteOwner`, and property-write permsissions
- Audit changes to certificate-template objects
- Review templates after any delegated administrative change
- Revoke certificates issued during an unauthorized configuration window

## Key takeaway

ESC4 showed that a template does not need to be insecure in its original state. Excessive control over the template is enoug hto create a certificate-based escalation path.
